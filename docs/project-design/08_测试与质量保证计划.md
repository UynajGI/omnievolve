# 测试与质量保证计划

## 1. 测试层级

| 层级 | 目标 | 典型内容 | 运行频率 |
|---|---|---|---|
| Unit | 函数/状态机/公式 | schema constraints、hash、UCB、metric 边界 | 每次提交 |
| Contract | 接口兼容 | SandboxBackend、TaskEvaluator、VectorBackend、Agent Protocol | 每次 PR |
| Integration | 多模块交互 | Sandbox+Evaluator、SQLite+Outbox、Agent+Scheduler | 每次 PR/夜间 |
| Security | 隔离与越权 | 网络、secret、mount、提权、fork bomb | 每日/发布前 |
| Fault Injection | 崩溃恢复 | kill -9、索引中断、重复回调、磁盘错误 | 每日/发布前 |
| Soak | 长时间稳定 | 500 候选、并发 worker、artifact 增长 | 每个阶段门 |
| Replay/Ablation | 搜索有效性 | memory on/off、novelty on/off、router replay | Phase 2/3 |
| E2E | 用户路径 | install→run→resume→best→audit | 发布候选 |

## 3. 质量门

### PR 门

- 类型检查、lint、unit、contract 全绿。
- A 级任务至少一个独立高级模型/人类审查。
- schema/protocol 变更必须有 ADR 和迁移。
- 安全相关 PR 不得只由原作者批准。

### Sprint 门

- 任务卡验收证据完整。
- P0/P1 缺陷分类与 owner 明确。
- 文档、配置、测试与实现同步。

### Release 门

- Phase 1 500 候选回归通过。
- 安全攻击测试全绿。
- E2E 安装矩阵通过。
- Audit 可还原最佳候选完整链路。
- 无未接受 P0；P1 必须写入 Release Notes。

## 4. 覆盖率要求

不以单一代码覆盖率替代质量，但建议：

- 核心状态机、事务、治理规则：分支覆盖 ≥90%。
- Adapter/Repository：语句覆盖 ≥80%。
- CLI/文档：以 E2E 可执行性为准。
- 安全测试和故障注入必须按场景覆盖，不以覆盖率折抵。
