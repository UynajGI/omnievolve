# 阶段四：低级模型投喂顺序

## 1. 投喂原则

每次只给一个闭合任务包，内容包括：

1. 任务卡全文；
2. 允许修改的文件白名单；
3. 只读依赖接口；
4. 明确禁止修改的 schema/Protocol；
5. 验收测试；
6. 输出要求：代码 diff、测试、变更摘要、未解决问题。

不得把整个仓库和一句“实现 S1”直接交给低级模型。

## 2. 推荐顺序

### Wave 0：确定性骨架

`S1-02 → S1-03 → S1-06 → S1-09 → S1-13/14/15`

### Wave 1：安全执行

`S2-01(A先冻结) → S2-03 → S2-04/05/06/07/08/09 → S2-10/11/12 → 测试`

### Wave 2：评估与状态机

`S3-01(A) → S3-02/03/05 → S3-06(A) → S3-07~12 → 测试`

### Wave 3：候选闭环

`S4-01/02/03 → S4-05/06 → S4-07 → S4-08~12 → S4-13~16`

### Wave 4：Agent

`S5-01(A) → S5-02~05 → S5-06/07/08 → S5-09~13 → 测试`

### Wave 5：检索

`S6-01(A) → S6-02/05 → S6-06/07 → S6-08/09/10 → S6-11/12/13/14 → 测试`

### Wave 6：长程搜索

`S7-01(A) → S7-02~04 → S7-05~09 → S7-10~15 → 消融/回归`

### Wave 7：健康度

`S8-01(A) → S8-02/03 → S8-04~09 → S8-11~14 → replay/tests`

### Wave 8：策略与发布

`S9-01(A) → S9-02~08 → CLI → audit → E2E → Go/No-Go`

## 3. 单任务投喂模板

```text
你只实现任务 Sx-yy。
允许修改：...
只读依赖：...
禁止修改：schema/protocol/security boundary...
必须新增测试：...
验收命令：...
输出：unified diff + 测试结果 + 变更摘要 + 风险。
若发现接口不足，只提交 change proposal，不直接改公共接口。
```

## 4. 高级模型回收检查

每完成 3–5 个 B/C 级任务，高级模型做一次：

- API drift 检查；
- 数据边界检查；
- 安全和幂等性检查；
- 重复实现/隐式状态检查；
- 与 WBS、ADR、测试证据对齐。
