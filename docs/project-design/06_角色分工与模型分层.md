# 角色分工与模型分层

## 1. 人类与模型职责

| 角色 | 负责 | 不负责 |
|---|---|---|
| 用户/产品 Owner | 优先级、scope cut、里程碑 Go/No-Go、目标任务 | 逐行实现 |
| 架构负责人/高级模型 | 数据边界、接口、关键路径、安全、评估语义、跨模块审查 | 大量重复 CRUD |
| 标准代码模型 | 中等复杂度模块实现、集成、主要测试 | 擅自改协议或安全边界 |
| 轻量代码模型 | 局部函数、类型、测试夹具、文档、CLI 小命令 | 跨模块设计与高风险代码 |
| 确定性工具 | 格式、迁移、静态检查、测试执行、依赖锁 | 架构判断 |

## 2. 模型等级

| 等级 | 使用场景 | 必须审查 |
|---|---|---|
| A | schema、事务、Sandbox、Evaluator、状态机、指标、Policy governance | 人类或另一高级模型双审 |
| B | Adapter、Repository、Agent 实现、检索、CLI | A 级审查接口和测试 |
| C | 单元测试、fixtures、文档、简单序列化 | B/A 抽查 |
| T | 格式化、类型检查、lint、测试、生成迁移 checksum | 自动化证据即可 |

## 3. 代码所有权

- `storage/schema.sql`、`uow.py`：ARCH/CORE 双 owner。
- `sandbox/`、`eval/evaluator_registry.py`、`meta/governance.py`：SEC owner，任何变更强制审查。
- `engine/scheduler.py`、`job_store.py`：CORE owner。
- `engine/memory.py`、`novelty.py`、`meta/policy_*`：SEARCH owner。
- `eval/metrics.py`、`health_policy.py`：EVAL owner。
- 发布分支：ARCH + QA 双签。

## 4. 低级模型禁止事项

- 不得自行增加数据库字段或修改唯一键。
- 不得把 trusted subprocess 设为静默默认。
- 不得在 evaluator 内直接运行候选代码。
- 不得将 health_score 写回 Candidate。
- 不得让 Meta-Agent 修改评分、测试或 hidden data。
- 不得用“先实现后补测试”跳过关键任务卡验收。
