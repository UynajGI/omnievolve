# OmniEvolve v0.2 项目总进度文档

## 1. 项目目标

交付一个 **Local-first、可恢复、可复现、可审计** 的代码自进化 Alpha：候选代码在隔离环境中执行；任务评估语义不可被元智能体修改；搜索过程健康度绑定策略版本和时间窗口；策略可版本化、导出和回滚。

## 2. 成功定义

### P0 必须达成

- 单任务连续执行至少 500 个候选，无已提交状态丢失或重复提交。
- 任意运行结果可追溯至 Artifact、父代、Prompt、模型、Evaluator、Environment、Policy 与 Seed。
- kill -9 后，已完成 EvaluationRun 不重复提交，过期任务可重新认领。
- 默认 Docker 候选无法访问宿主 API Key、非授权文件和外部网络。
- Task semantics、正确性测试、隐藏数据、评分公式和聚合规则不可被 Meta-Agent 修改。
- SQLite 与向量索引中断后可自动 reconcile。
- Champion Policy 可完整导出、应用和回滚。

### P1 应达成

- 多级 NoveltyGate 不是单 cosine 一刀切。
- 记忆检索、引用、采用和结果可追踪。
- ROI、覆盖率、记忆有效性、污染度有可计算定义与边界测试。
- Director/Coder/Critic 模型收益分开统计。

## 7. 用户需要拍板的事项

### M0 启动前

- 是否接受“首版只支持 Python 候选”的 scope cut。
- 是否接受 DockerBackend 为默认，Windows 原生只提供 trusted mode/WSL 路径。
- 是否接受 v0.2 仅做 L0 元进化，不做 Prompt 自动晋升与 Agent 代码自修改。
- 是否将 zvec 保持为 optional extra，并保留 NumPy fallback。

### M2 Phase 1 后

- 安全/恢复验收未通过时，是否停止一切 Agent 与搜索扩展。默认答案：停止。

### M3 Phase 2 后

- Novelty/Memory 是否产生可测收益；若无收益，先修数据和检索，不进入复杂 MCTS。

### M4 Phase 3 中

- 健康指标是否足够稳定支持 L0 自动调参；若不稳定，仅提供建议，不自动应用。

### M5 发布前

- 是否达到 Alpha，而非 Demo：安装、恢复、审计、故障诊断和文档必须可用。
